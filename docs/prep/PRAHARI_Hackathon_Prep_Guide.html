1. Executive summary

Problem

Drug, arms, fake-document and mule-account sellers advertise on public Telegram channels and social media in coded Hinglish and emojis. Analysts read channel by channel, and seller identifiers (phone, UPI, handle) are rarely collated across channels.

Solution: PRAHARI

A web dashboard that imports or collects public posts, flags illegal-sale ads with slang-aware rules, extracts seller identifiers, links the same identifier across channels, scores risk with stated reasons, shows it on a Rajasthan district map and exports an evidence dossier.

How it works in 5 lines

  1. Collect: CSV/JSON import, pasted text, screenshots (text read in the browser), or a public Telegram preview scan (no login).
  2. Classify: 232-term lexicon (English, Hinglish, Devanagari, emoji) with context rules; a lone keyword needs a second signal; optional Gemini second opinion.
  3. Extract: phone, UPI, @handle, crypto wallet, bank account, IFSC, district, and whether the ad sells, buys or rents.
  4. Link: identifier graph across channels, near-duplicate text and near-identical images.
  5. Alert: risk-scored alerts with evidence (text, time, channel, SHA-256), analyst status, a hash-chained audit trail, re-verify, export and a PDF dossier.

Three headline impact points (measured on our test set)

  • Imports, scores and stores 500 posts in about 2 s or less (1.3 s in our latest run); rules take about 0.5 ms per post.
  • Every flag is explainable: matched words highlighted, risk reasons listed, analyst decisions logged.
  • Cross-channel linking turns separate ads into a lead: one handle in three demo channels, one UPI in a drug ad and a mule-account ad.

What is unique

Context-aware slang rules that also see through common disguises, a transparent additive risk score, identifier and image linking on a district map, and an evidence record you can re-verify that is explicit about its own limits.

Measured numbers (synthetic data, from the repo)
  • Lexicon: 232 terms, 4 categories. 92 automated backend tests pass.
  • Dev set (n=60, used for tuning): precision 100%, recall 83.3%.
  • Held-out set (n=50, never tuned on): precision 94.4%, recall 68.0%, accuracy 82.0%; F1 about 0.79.
  • Evasion check: 45 hand-written disguise cases (spaced digits, look-alike letters, zero-width characters...) pass, after fixing a typo in 2 test inputs.
  • All of these are on posts we wrote. With n=50 one post moves a percentage by 2 points or more.
Honest limits (say them first)
  • Not a trained ML classifier: rules + lexicon, optional Gemini, ML-style similarity (TF-IDF, perceptual hash).
  • Real-world accuracy not measured; needs a labelled set such as the R4C sample.
  • Hash is a content digest, not a legal certificate; audit log is tamper-evident, not authenticated (no logins).
  • On-demand scans, not 24x7 monitoring; free-tier hosting; synthetic demo data.

Appendix B. How to measure precision, recall and F1 on the R4C labelled set

  1. Create a CSV with columns text,label where label is DRUGS, ARMS, DOCUMENTS, FINANCIAL or NONE.
  2. Split it (for example 50/50, stratified by label). Tune the lexicon only on the first half.
  3. Score the second half the way backend/eval_classifier.py does: for each category count TP, FP, FN.
  4. Precision = TP/(TP+FP); Recall = TP/(TP+FN); F1 = 2PR/(P+R). Also report overall accuracy and the confusion matrix.
  5. Add a 95% Wilson interval for each ratio and say the sample size next to every number.
  6. Report the rules-only result and, separately, the result with Gemini enabled. Until this is run on real labelled data, real-world figures are to be measured.
