1. Executive summary

Problem

Drug, arms, fake-document and mule-account sellers advertise on public Telegram channels and social media in coded Hinglish and emojis. Analysts read channel by channel, and seller identifiers (phone, UPI, handle) are rarely collated across channels.

Solution: PRAHARI

A web dashboard that imports or collects public posts, flags illegal-sale ads with slang-aware rules, extracts seller identifiers, links the same identifier across channels, scores risk with stated reasons, shows it on a Rajasthan district map and exports an evidence dossier.

How it works in 5 lines

  1. Collect: CSV/JSON import, pasted text, or a public Telegram preview scan (no login).
  2. Classify: 189-term lexicon (English, Hinglish, Devanagari, emoji); ambiguous words need sale context; optional Gemini second opinion.
  3. Extract: phone, UPI, @handle, crypto wallet, bank account, IFSC, district.
  4. Link: identifier graph across channels and near-duplicate ad grouping.
  5. Alert: risk-scored alerts with evidence (text, time, channel, SHA-256) and a PDF dossier.

Three headline impact points (measured or stated)

  • Imports and scores 500 posts in about 1.5 s on the demo backend; rules take about 0.6 ms per post.
  • Every flag is explainable: matched words highlighted, risk reasons listed.
  • Cross-channel linking turns separate ads into a lead: one handle appears in three demo channels.

What is unique

Context-aware slang rules (ambiguous words need sale context), a transparent additive risk score, identifier linking on a district map, and an evidence record that is explicit about its own limits.

Measured numbers (from the repo)
  • Lexicon: 189 terms, 4 categories.
  • Dev set (n=60, used for tuning): precision 100%, recall 83.3%.
  • Holdout (n=50, never tuned on): precision 89.5%, recall 68.0%, accuracy 80.0%.
  • F1 computed from those: about 0.91 dev, about 0.77 holdout.
  • Sets are synthetic and keyword-style; 95% interval on holdout precision is about 0.69-0.97.
Honest limits (say them first)
  • No trained ML; rules plus optional Gemini.
  • No OCR or image similarity; no SIM or buy/sell/rent detection.
  • Hash is a content digest, not a legal certificate; no signature or chain; not re-verifiable in-app.
  • No login; free-tier hosting; synthetic demo data.

Appendix B. How to measure precision, recall and F1 on the R4C labelled set

  1. Create a CSV with columns text,label where label is DRUGS, ARMS, DOCUMENTS, FINANCIAL or NONE.
  2. Split it (for example 50/50, stratified by label). Tune the lexicon only on the first half.
  3. Run python backend/eval_classifier.py style scoring on the second half: for each category count TP, FP, FN.
  4. Precision = TP/(TP+FP); Recall = TP/(TP+FN); F1 = 2PR/(P+R). Also report overall accuracy and the confusion matrix.
  5. Add a 95% Wilson interval for each ratio and say the sample size next to every number.
  6. Report the rules-only result and, separately, the result with Gemini enabled. Until this is run the figures are to be measured.
